🧠 Rule Engine Defaults

Set page-level defaults applied to all rows across all selected providers. Per-row CSV columns override these. Conflicts with filters above are flagged in red.

Rule descriptions ▸
Rule Effect (all providers)
ENV=Production Excludes burstable (t-family / B-series / e2-shared), enforces current-gen, min 4 vCPU for web/DB. AWS also requires Nitro under Compliance.
OS=Windows De-prioritises ARM/Graviton families across all providers; prefers Intel or AMD
Workload=Database AWS r-family first · Azure E/M-series first · GCP n2-highmem/m1 first
Compliance=HIPAA/PCI Excludes burstable; enforces current-gen. AWS: requires Nitro-capable.
Min Gen=m6/v4/N4 Excludes older generations: m5/r5 (AWS), Dsv3/Esv3 (Azure), N1 (GCP). Useful as m5 approaches EOL.
Workload=SQL Server Enforces a 4-vCPU licence floor when it can — SQL Server is licensed per core (minimum four), so a smaller box saves no licence cost. If no eligible candidate is that large, the fallback pick is kept and the rule is reported as not applied.
Workload=ML/AI (GPU) Requires a GPU/accelerator instance; every other workload excludes accelerators, so a GPU box is not recommended by accident. If the pool has no accelerator to offer, the fallback pick is kept and the rule is reported as not applied.
