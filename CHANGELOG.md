## Versioning & tags

The project follows **Semantic Versioning** (`MAJOR.MINOR.PATCH`):

- **MAJOR** — a platform-defining shift (1.x single→multi-cloud foundation,
  2.x rule engine and pricing removed from outputs, 3.x the modern app).
- **MINOR** — a feature release; the `### x.y` headings in the version map and
  the narrative release notes below correspond to these.
- **PATCH** — an individual commit within a release (a feature increment, fix,
  review round, docs, or formatting pass).

The **version map** below assigns every commit since the first a version and
describes what its change actually did. The 95 commits that predate the first
tag (`v3.4.9`) keep their original commit messages unchanged; this table is the
reconciled, readable record on top of them. Versions are no longer printed in
the README, the user guide, or anywhere else in the product — they live here
and in git tags, so there is nothing to bump by hand.

**Tags.** Commits from `3.4.9` onward carry an annotated git tag of their
version. The 95 commits before that tag are catalogued here but not tagged —
which is where the count comes from: every row in the map is either one of those
95 or one of the tagged commits. Going forward, each commit is tagged with its version when
it lands. A tagged commit's version is recoverable with `git describe --tags`;
the untagged historical commits are resolved through this version map.

The newest row uses `_this commit_` in place of a SHA because a commit cannot
contain its own hash; the next commit backfills it with the real short SHA, so
exactly one row (the current tip) ever carries the placeholder.

## Release notes

Newest first. Readable summaries of each feature release; per-commit detail is
in the version map above.

### 3.9 — 2026-07-19 → 2026-07-21

Recommendation intelligence: teach the engine _how_ to size, not just what to
map to. The sizing logic now reasons about the statistic behind a number, the
workload behind a VM, and — across clouds — the _kind_ of machine each provider
landed on.

- **Size against a percentile, not just the average.** A "Size against" control
  offers Average, p95 or Peak, and a new **`Sized On`** column reports, per row,
  the statistic actually used. Sizing on an average silently undersizes a bursty
  VM — a box averaging 20% with a p95 of 85% is not a downsize candidate, but the
  average alone says it is. CPU and memory resolve **independently**, each walking
  its own fallback chain and preferring the higher remaining statistic, because
  falling to a lower one under-provisions. (In passing, `maxcpu` / `maxmemory`
  headers were being read as the _average_ column — a peak reading drove sizing
  while labelled an average — now mapped to the peak canonicals.)
- **Workload-aware rules.** A row tagged **ML/AI (GPU)** now requires an
  accelerator, and every other workload excludes one, so a plain VM never lands on
  a GPU box and a GPU fleet is not silently downsized onto CPU-only hardware.
  **Dev/Test** at low utilization prefers a **burstable** family (the run's own
  low-use thresholds decide "low", and only a measured-low CPU counts — an unknown
  CPU is not evidence a box idles). **SQL Server** carries a 4-core license floor,
  since Microsoft bills a minimum of four core licences per VM regardless.
- **Storage pass-through.** An optional **`Disk (GB)`** column flows through to the
  outputs and fills the AWS bulk template's storage field, which had always shipped
  blank. Memory and disk share one unit path, so a `Provisioned MiB` column is
  converted rather than read as GB (a silent 1024×), and disk sizes **round up** —
  a passthrough must never hand back less than the upload carried. Storage never
  moves a recommendation.
- **Multicloud family-equivalence explainers.** A multi-cloud run now carries one
  **`Family Equivalence`** column reading whether the clouds landed on the same
  _kind_ of machine — `General purpose on AWS, AZURE, GCP` when they agree, and the
  more useful `Differs — AWS Memory optimized, GCP General purpose` when they do
  not — folded from each cloud's own family classification.

**Corrections that changed recommendations.** The GPU classifier was wrong two
ways against real region data: provider-agnostic prefixes called Azure's G/GS
(memory-optimized) and Dl-series (general-purpose) GPUs — 60 instances in one
region — and it tested for "accelerated" while GCP writes "Accelerator optimized",
so GCP's accelerator families slipped through the exclude. Before the rule, plain
requests were picking accelerators at ordinary sizes. Separately, a disk column in
MiB mapped through the column panel was renamed to `Disk (GB)` without the ÷1024,
overstating every disk 1024×. Both fixed and pinned by tests. The engine's
recommendation goldens are otherwise unchanged across the line — the new columns
are additive.

### 3.8 — 2026-07-16 → 2026-07-19

Results, visualization and reporting: make a run something you can explore,
present, and trust.

- **The results table became a table.** Pagination (25/50/100/All), per-column
  filters, column show/hide, and a "no-match only" view — applied in that order,
  so a page is a window onto the filtered-and-sorted set rather than a slice of
  raw rows. The clipboard copies exactly what the screen shows.
- **Charts, hand-built and dependency-free.** A match-rate **meter** (not a
  two-slice donut, which asks the eye to compare angles for something one length
  states exactly), a family distribution per provider, and vCPU/GiB before→after
  as **two charts, never one** — a dual-axis chart invents a crossover wherever
  the axes happen to be zeroed. Colours are theme tokens whose steps are chosen
  per mode against that mode's own surface, never flipped automatically.
- **An executive print report.** One print-optimized page — headline stat tiles
  (VMs assessed, matched, no-match, applications), a per-provider right-sizing
  line and the three charts — behind a Print Report button, forced to light
  tokens because printing a dark surface wastes ink and reads poorly.
- **Top-3 alternatives per row.** Every recommendation now carries three labelled
  strategies — Most Cost Optimized, Workload Based, Newest Generation — as
  columns and as their own Excel sheets, so the tradeoff is visible instead of
  collapsed into one answer.
- **A fit / headroom flag.** An over-provisioned like-for-like match is marked
  with how much spare capacity it leaves, so "it fits" and "it fits well" stop
  looking identical.
- **Scenario comparison v2.** Name your runs and compare any number of them
  side by side, with the configuration diff and the changed rows exportable as
  CSV. (Saving scenarios across sessions is deferred to 3.10, where the storage
  manager adds the quota handling it needs.)
- **App Portfolio polish.** In-dashboard filters, per-app CSV, and a cosmetic
  pass over the rollup.
- **Excel is the primary output.** One Download Results (Excel) button produces
  the full workbook; the flat CSVs move into a multiselect dropdown where you
  tick the ones you want.

**Corrections that changed recommendations.** A workload preference could
override size fit entirely, so a 2 vCPU / 4 GB cache VM was matched to a 32 vCPU
/ 976 GiB instance — worst on GCP, whose memory-optimized families have no small
member. A preferred pick is now bounded to a sensible multiple of the
requirement. Separately, **Min Gen was misread twice**: the Azure version parse
read an instance's _size_ as its generation (`nv48sv3`, a v3 machine, scored as
generation 48), and a single number meant different things on different pages —
which made the Azure page's own "v5+" option quietly filter to v3+. Min Gen is
now native to each cloud, with one control per provider on the multi-cloud page.

**Before publishing**, the vendored-dependency check found that the styling
engine — a fork of SheetJS 0.18.x, below the fixes for CVE-2023-30533 and
CVE-2024-22363 — could end up parsing an uploaded file, because both vendored
bundles define `window.XLSX` and the upload guard accepted whichever had loaded
last. Reads are now pinned to the patched build and writes to the styling one.
See the assessment of record in [SECURITY.md](SECURITY.md).

### 3.7 — 2026-07-12 → 2026-07-14

Ingestion and input quality: meet the inventory where it actually comes from,
and refuse to guess at what it means.

- **Import presets for real tools.** An **RVTools** export or an **AWS
  Application Discovery Service** template now loads with nothing to map. Each
  preset identifies a format by headers only that tool ships, then settles what
  the generic matcher cannot: which column is the vCPU count (ADS reports
  sockets, physical cores and logical cores — the last is the answer), what units
  the header hides, and — through a derivation — a column the format carries only
  implicitly. ADS reports memory _used_ in megabytes, so the memory utilization
  the optimizer needs is computed from it.
- **Excel workbooks open the right sheet.** A multi-sheet workbook opens the sheet
  that looks most like a VM inventory rather than the first one, and a picker lets
  you switch. A sheet a preset recognises wins over any amount of generic column
  counting — on a real RVTools export, `vHost` (the ESXi servers) otherwise
  outscored `vInfo` (the VMs), and the wrong machines were loaded entirely.
- **Memory units are converted only on evidence.** A header that says `MB`, or a
  preset that knows the format's convention. When neither does, the file can only
  raise the _question_: a fleet whose median memory is implausible as GB is
  reported with both answers offered, and nothing is touched until one is given.
  There is deliberately no code path that converts on the values alone — a real
  fleet of 512 GB–1 TB machines exists, and halving it by 1024 corrupts it exactly
  as badly as leaving RVTools' MiB alone.
- **An input check before the run, not after.** Rows that cannot size sensibly —
  missing or zero CPU or memory, figures no provider sells, utilization above
  100% — are named with the row numbers a spreadsheet shows. Repeated VM names are
  a _question_ (merge, or keep them as separate machines), not a verdict.
- **A column mapping panel, and mappings that are remembered.** Anything ambiguous
  or missing opens a panel rather than being guessed at, and a confirmed answer is
  saved against that file's set of headers and replayed on the next upload. Saved
  mappings are listed and can be forgotten.
- **Four ways in.** Upload (CSV or `.xlsx`, including drag and drop), **paste**
  straight from a spreadsheet, **manual entry** — which can now add several
  similar VMs at once and copy a row — or one of three **sample datasets**: a
  small clean one, a 500-VM one that shows what a real batch looks like, and a
  deliberately messy one that trips the input check on purpose.
- **`Current Instance Type`** — a row can carry the size it runs on today, carried
  through to the preview and every export beside the recommendation that would
  replace it. It does not affect sizing.
- **Results say when they are stale.** Replacing the data a run was computed from
  now marks the results stale, not only changing the provider selection.

The bugs this release found in itself are the interesting part, and all of them
were of one kind: **a wrong answer that looked entirely normal.** RVTools writes
memory with a thousands separator, and `parseFloat("16,384")` is `16` — read as
MiB and divided, a 16 GiB VM arrived as 0.02 GB and every machine in the file
sized to the smallest instance on offer, with nothing failing and no warning
raised. `Host` was a VM-name synonym while `VM` was not, so every guest silently
took its hypervisor's name. A recognised MiB file could still be read as GB on a
page without the mapping panel, off by 1024. Two columns with the same name
collapsed into one, and the mapping panel then offered two choices that were
secretly the same column. None of these would have failed; all of them would have
been believed.

Both presets exist because a real export contradicted what a specification would
have said. **Azure Migrate is not implemented and is not scheduled** for that
reason: it needs a genuine export, and a mapping written from documentation would
mis-map silently — which is worse than the mapping panel, which already handles
unknown files correctly.

### 3.6 — 2026-07-12

Output fidelity and UI polish: what you see on screen and what lands in the
downloaded file now agree, and the interface stops interrupting you.

- **Toasts instead of `alert()`** — every blocking browser dialog is gone,
  replaced by a themed, dismissible toast stack that respects dark mode and
  never freezes the page.
- **Spreadsheet-safe CSV exports** — every download goes through one helper that
  writes a UTF-8 BOM, so accented and non-Latin VM names survive the trip into
  Excel. The AWS bulk template is deliberately exempt: the Pricing Calculator
  parses that file, and a BOM corrupts its first header.
- **Copy to clipboard** — the results table, or any single row, can be copied as
  TSV and pasted straight into a spreadsheet. What you copy is exactly what the
  preview is showing, filter and sort included.
- **One-click filter relaxation** — when rows fail only because of a single
  filter, the nearest-miss analysis now offers a button that turns that one
  filter off.
- **Per-provider sizing savings** — a chip summarising how much smaller the
  recommended instances are than the source VMs, per provider (never summed
  across providers, which would be meaningless).
- **Sections remember themselves** — the sample template and advanced filtering
  start collapsed and each page remembers what you opened or closed. A
  back-to-top button appears on long pages.
- **A landing page that explains the tool** — a feature overview and a
  what's-new teaser, so a first-time visitor can tell what this does without
  opening it.

Hardening, from this release's own review rounds: copying to the clipboard was
missing the formula-injection guard the CSV export already applied, so a VM
named `=cmd…` could have executed on paste. The vendored spreadsheet bundles now
carry recorded SHA-256 checksums, pinned against git's line-ending translation
so they are byte-identical to upstream on every platform.

### 3.5 — 2026-07-10 → 2026-07-12

UI polish, project foundations, and the patch-level known issues.

- **Download section grouping** — the post-generation buttons now sit in
  labeled clusters (Results / AWS Pricing Calculator / Analysis) instead of a
  flat button run; the Analysis cluster hides itself when empty. Also fixed the
  Results Excel button being destroyed on the AWS page after every generation.
- **Scenario comparison config diff** — comparing two pinned runs now shows a
  "Configuration changes (A → B)" table of every setting that differed
  (recommendation type, providers, filters, thresholds, rule defaults, and
  per-provider filter selections). Comparison outcomes are announced to screen
  readers via a polite live region, and the changed-rows table scrolls under a
  sticky header.
- **Preset inline dialogs** — saving a preset uses an inline name form and
  overwrite/update/delete use two-step confirm buttons, replacing the native
  `prompt()`/`confirm()` dialogs.
- **Preset export/import** — a page's presets can be downloaded as a JSON file
  and imported elsewhere; imports validate the file shape and merge without
  overwriting (name collisions get an " (imported)" suffix). Preset names that
  collide with `Object.prototype` (`__proto__`, `constructor`, `prototype`) are
  rejected on save and import.
- **Offline indicator** — every page shows a small banner while the connection
  is down and a short "Back online" notice on reconnect.
- **Nearest-miss probe coupling test** — a source-scan test now enforces that
  every filter option a provider's `applyFilters` reads has a matching
  nearest-miss probe, so the Nearest Miss column can't silently under-report.
- **Housekeeping** — project history moved to this changelog as a per-commit
  version map; a roadmap was added; hardcoded versions were removed from the
  README and user guide (versions now live only in the changelog and git tags);
  the unused `docs/user-guide.pdf` was removed; SemVer git tagging was adopted.
- **One upload pipeline** — the legacy file handler is gone. It was not merely
  dead code: it attached a second listener to the file input and raced the real
  one for the status, statistics, and preview panels, rendering them in
  hardcoded light-mode colours. Drag-and-drop and the size/empty guards, which
  existed only there, moved into the surviving path.
- **Uploads are routed by content, not by file extension** — a workbook renamed
  `.csv` used to be read as text and parsed into garbage rows; it now reads
  correctly, while images, PDFs, and other binaries are refused instead of being
  fed to the CSV parser.
- **Exports agree with the preview** — a download now follows the sort order on
  screen, still contains every row while the preview is filtered (and says so),
  and every generated file has a consistent, dated filename in the user's local
  day.
- **Stale-results notice** — changing the provider selection after a run marks
  the table and downloads as stale, since they still describe the providers that
  were selected when Generate was clicked.
- **Project foundations** — Prettier pinned with a CI formatting gate (and a
  `.prettierignore` shielding the vendored builds, generated region data, and
  golden fixtures); a security policy documenting the vendored libraries and a
  CVE-watch routine; a "nothing leaves your browser" privacy statement on the
  landing page; `RELEASING.md`; and a rule for when a data refresh requires a
  service-worker cache bump (only when region files are removed, since a deleted
  file would otherwise be served from cache forever).
- **Coupling tests** — a pinned scenario must survive a later run and a preview
  sort, and the manual-entry region autocomplete must offer every region the
  upload's chips accept.
